# 本机运行与基本检查

## 项目和入口

- 项目：`D:\市场开发\外贸开发信小助手`
- 默认地址：`http://127.0.0.1:3000/`；实际端口以 `data/runtime.json` 和健康接口为准。
- 启动：用户可双击项目内 `启动助手.bat`。维护时可在 PowerShell 中运行 `启动助手.ps1 -NoBrowser`，再用健康接口确认服务就绪。
- 关闭：使用 `关闭助手.bat` / `关闭助手.ps1`，不要随意结束同名 Node 进程。脚本会校验进程并保留数据库。
- 状态：`查看状态.bat`。也可只读检查 `/api/health`、`/api/summary`、`/api/sync`。

## 判断应用是否真的运行

1. 读取 `data/runtime.json` 中的端口和进程身份，不展示无关环境变量。
2. 请求 `http://127.0.0.1:<端口>/api/health`。
3. 必要时检查该端口监听进程的可执行文件和命令行是否指向本项目 `server.js`。
4. 页面打不开时先区分：服务未运行、端口不同、页面缓存、浏览器权限提示、应用自身错误。不要把其中一种猜成另一种。
5. 前端脚本有更改时，提示用户刷新页面；涉及后端模块时按项目脚本优雅重启，再复查健康接口和具体业务接口。

## 安全和恢复

- 本地应用只应绑定回环地址 `127.0.0.1`，不要把端口暴露到公网。
- 服务重启不应删除 `data`、`mail.protected.json`、数据库或监督器记录。
- 数据变更前用 SQLite 在线备份或一致性备份并验证 integrity；不要直接改生产数据库绕过正常审核接口。
- 403 `安全校验失效，请刷新页面后再操作` 属于页面会话/CSRF链路。刷新或重新进入页面后，用正常 UI 流程重试；不得关闭 CSRF 校验、硬编码令牌或直接改库。
- `spawn EPERM`、网站 503、登录失效、权限拒绝是不同故障。依据原始日志定位，不统一归因于权限或登录。

## 时间和日志

- 面向用户的时间采用北京时间（Asia/Shanghai）。数据库常以 ISO UTC 保存；展示时显式转换。
- 定时窗口为北京时间 07:30、14:00、19:00。只凭任务配置不能证明实际运行；核查每轮运行 ID、计划时间、实际开始/结束、平台状态和结果。
- 电脑关机、休眠、程序关闭或账户未登录时，不声称后台采集已执行。补采标记为补采，不能伪装成原时段执行。
- 报错报告摘取阶段、错误类型、清理后的错误信息和时间；去除凭据、cookie、token、个人邮箱及不必要的本机路径。

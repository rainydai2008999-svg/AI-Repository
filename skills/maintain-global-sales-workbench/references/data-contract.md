# 数据合同与核验规则

## 客户记录

| 字段 | 规则 |
|---|---|
| `company` | 邮件签名、附件客户名或已确认别名；不得按邮箱前缀猜测 |
| `contact` | 收发件人显示名或签名姓名 |
| `role` | 仅取签名或正文明确职位 |
| `email` | 原始企业或公共邮箱；追踪包装地址应还原为可见真实地址 |
| `secondary_emails` | 同一已确认客户的其他邮件地址 |
| `phone` | 仅取签名、正文或附件明确号码 |
| `website_domain` | 非公共邮箱的 `@` 后缀；仅按用户要求生成访问入口 |
| `country` | 地址、签名、附件或已核验网站明确国家；域名后缀不能单独证明国别 |
| `latest_date` | 客户相关邮件或业务记录中的最新日期 |
| `source_link` | Outlook 原邮件、附件或公开页面 |

## 报价记录

| 字段 | 规则 |
|---|---|
| `quote_date` | 邮件正文、附件报价日期或文件明确日期 |
| `customer` | 与客户主记录匹配；无法匹配时保留原名并标记待确认 |
| `product` | 原文产品名 |
| `model` | 原文型号；不得从相似产品推断 |
| `unit_price` | 原文数值，不自行补税费或运费 |
| `currency` | 原文币种；缺失时留白 |
| `unit` | 原文单位并做受控规范化 |
| `quantity` | 原文数量；MOQ 与订单数量分开理解 |
| `line_total` | 仅取原文；除非用户明确要求，否则不自行计算 |
| `trade_term` | 原文 Incoterm 与地点 |
| `payment` | 原文付款条件 |
| `source_name` | 邮件主题或附件文件名 |
| `source_link` | 原邮件链接 |

## 单位规范化

- `pc`, `pcs`, `piece`, `pieces` → `pc`
- `set`, `sets` → `set`
- `kg`, `kgs` → `kg`
- `mt`, `metric ton`, `metric tons` → `MT`
- `m2`, `m²`, `sqm` → `m²`

不得自动换算质量、长度、面积或包装单位。

## 客户身份规范化

基础规范化仅包括去首尾空格、合并连续空格、统一大小写。法律后缀、品牌、DBA、集团和个人姓名需要证据映射。别名表必须保存规范名、别名和依据。

## 价格选择键

```text
canonical_customer + (model || normalized_product) + currency + normalized_unit
```

只有键完全相同才比较 `unit_price`。最低价相同时选择 `quote_date` 较新的记录，并保留观察次数和原始来源。

## 空值与状态

- 未提供：空字符串或 `—`。
- 未接入：数据源尚未连接。
- 未见成交证据：当前来源没有订单或付款证据，不等同于确认未成交。
- 待确认：存在可能匹配但证据不足。
- 已核验：字段能追溯到明确来源。
- 潜在判断：销售分析，不是客户事实。

## 异常清单

将以下情况保留为异常，不要自动修复：同名客户对应不同域名；同域名出现明显不同公司名；同型号缺少币种或单位；数量、单价和原文合计不一致；邮件正文与附件条款冲突；追踪邮箱无法还原；网站域名来自公共邮箱；客户回复、成交或付款证据不足。
